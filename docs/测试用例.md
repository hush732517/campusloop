### 图形化视图的专门验证：`docs/measure.mjs`

DOM 断言只能证明「元素存在」，无法证明「元素被摆在了正确的位置」。
时间轴这类图形化视图的正确性在于**坐标**，因此额外提供了 `measure.mjs`：
它通过 Chrome DevTools Protocol 读取**真实布局盒模型**，用来核对——

- 活动块的 `top/height` 是否与时间成正比（实测刻度间距恒为 30px/小时）；
- 刻度标签是否真的落在左侧刻度栏内（实测 100/100 全部在栏内，未被裁切）；
- 并排的活动块是否真的不重叠；
- 整点刻度是否对齐整点（曾发现紧凑模式下产生 `13:40 / 14:40` 这类刻度，已修正）；
- 页面是否出现横向溢出（实测无）。

### 测试驱动发现的真实缺陷（均已修复并加回归断言）

| 缺陷 | 现象 | 修复 |
| --- | --- | --- |
| 冲突噪音过多 | 某活动 23:53 结束、另一活动 23:59 截止，被判定为「时间冲突」，提醒失去价值 | 增加 15 分钟最小重叠阈值 |
| 风险内容完整度虚高 | 填满表单的高风险兼职信息拿到 72 分完整度，与「不可信」自相矛盾 | 命中风险特征时封顶：高风险 ≤ 45、中风险 ≤ 65 |
| 清空数据后旧数据残留 | `clearAll()` 替换了缓存对象，但视图闭包中已持有的数组引用仍指向旧数据 | 改为**就地清空**（`length = 0`），并对 `importJSON` 做同样处理 |
| **补充通知丢弃了原始信息** | 展示层保留了补充通知、隐藏了原始通知，导致训练营卡片显示「报名截止未注明」——而 9/24 22:00 这个截止时间恰恰写在原始通知里；双创招募卡片同样丢了截止时间 | 改为「**显示原始通知（叠加变更），补充通知作为通知记录**」：卡片用原始通知的标题与未被修订的字段，同时叠加上补充通知带来的时间与地点变更；直接访问补充通知的详情页会规范化为原活动的完整视图 |
| **信息体检统计自相矛盾** | 体检面板写「有 0 条已被后续补充通知更新」，但页面上明明有卡片标着「信息已更新」 | 统计口径改为「发生字段级变更的条目数」，并传入全量数据而非可见列表 |
| **状态标签与结论行互相矛盾** | 学习小组卡片左上角标「无需报名」，下面结论却写「需报名（截止未注明）」 | 周期 / 长期类活动若需要报名，状态改为「报名中 / 长期可报名」并注明「满员即止」 |
| 年级展示冗余 | 面向全体本科生的赛事显示成「大一、大二、大三、大四可参加」 | 年级覆盖全部时简化为「全校可参加」 |
| **时间轴活动块排版错乱** | 「单行紧凑块」的高度阈值写成 44px，而两行内容实际只需约 32px，导致 42px 的块也被当作单行：标题与时间被 flex 推到块的左右两端，中间留出大片空白，整页看起来像排版错乱 | 阈值下调为 32px，只有真的放不下两行时才并排显示；并补充 `measure.mjs` 的几何回归守卫（按真实盒模型判断「排成单行的块是否确实高度不足」），已用 CDP 注入旧样式验证该守卫确实会失败 |
| 当前时刻标签溢出卡片 | 「现在 14:00」标签用 `top: -8px` 定位在线条上方，溢出到了卡片标题区 | 改为 `top: 50%` + `translateY(-50%)` 居中于红线 |
| 紧凑模式刻度不落在整点 | 时间轴起点为 13:40 时会得到 13:40 / 14:40 / 15:40 这类刻度，与「按小时读时间轴」的预期不符 | 刻度从 `lo` 之后的第一个整点起算 |
| 时间轴空白过多 | 全天模式下 9/19 的泳道高达 704px，其中大半为空白 | 新增紧凑 / 全天两种缩放，紧凑模式按当天实际活动收紧（实测降到 212px） |

> 后三项由 `docs/browsertest.mjs`（真实浏览器）发现——前四套基于 DOM 桩的测试只断言了
> 「某个 id 在不在列表里」，没有断言「卡片上到底显示了什么」，因此漏掉了这类**展示层**缺陷。
> 这也说明了为什么在提交前必须用真实浏览器再核对一遍。
